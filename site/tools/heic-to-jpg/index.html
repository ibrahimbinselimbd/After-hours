KNOW WHAT YOU’RE GETTING / 04

A format switch. Not a black box.

01 / LOCAL ENGINEPrivate, by construction.

A dedicated browser worker decodes each photo. JPG output is checked before download. No analytics, image uploads or server-side conversion.

02 / HONEST OUTPUTThe still photo, not everything.

Only the primary still image is exported. EXIF, GPS, camera metadata, HDR detail, depth maps and Live Photo motion/audio are not preserved reliably. JPEG transparency is flattened to white.

03 / DEVICE-AWARESome files need another route.

HEIC variants, damaged files and device limits can prevent conversion. Decode limits are checked before full pixel rendering. Large photos may require a desktop. No promise of universal support or smaller files.

What happens to my originals?

Nothing. Originals are read locally and never modified. Refreshing or clearing the queue removes this page’s results, so download JPGs before leaving.

How do quality, retries and credits work?

Settings apply when a queued or failed file starts converting. Files added during a running batch wait for the next run. Cancel is disabled briefly while a verified result is committed. Completed results keep their original settings. To change a completed output, remove it and add the original again; a new successful conversion uses another credit. Retrying a failed conversion uses a credit only if it succeeds. Pause lets the current photo finish, then stops the queue.

What are the safety limits?

Up to 10 queued files, 20 MB each, 80 MB combined. One worker per image is released immediately afterward. Outputs stay in memory until removed or the page is closed. Downloads are limited to a 100 MB ZIP; use individual downloads for larger results.

Will every HEIC look exactly like my iPhone preview?

No. Codec support, color profiles, HDR-to-SDR rendering and orientation in unusual files can vary. Inspect the JPG preview before using the result. For archival fidelity, retain the original HEIC and its companion files.
